# TDD Implementation Skill

このスキルは、テスト駆動開発（TDD）のサイクルを用いて、新しいエージェント機能を安全かつ高品質に実装するために使用します。

## ワークフロー

以下のステップを順番に実行します。

### 1. 仕様のヒアリング
ユーザーから実装したい機能の仕様を詳細に聞き出します。
- 目的、入力、出力、前提条件、処理手順、判断基準、例外処理、完了条件を明確にします。
- 不明な点がある場合は、推測せずにユーザーに質問してください。
- 仕様が確定するまで次のステップに進まないでください。

### 2. テストの作成 (Red)
確定した仕様に基づき、まず失敗するテストコードを作成します。
-  ディレクトリ、または機能に関連する適切な場所に  用のテストを作成してください。
- テストを実行し、意図通りに失敗することを確認してください。

### 3. 実装 (Green)
テストをパスさせるための最小限の実装を行います。
-  ディレクトリ内の適切な場所にコードを実装します。
- 実装後、作成したテストを実行し、すべてパスすることを確認してください。

### 4. 品質ガードの実行
実装がプロジェクトの規約に準拠しているか確認します。
- `scripts/quality_guard.sh` を実行してください。
- Lintエラーやフォーマットエラー、テスト失敗がある場合は、修正して再度品質ガードを通してください。

### 5. 振り返り (Retro)
実装が完了し、品質ガードを通過した後、次のスキルチェーンである `retro` を呼び出します。
- `retro` スキルを呼び出し、今回の実装プロセスに関する振り返り（KPT）を行わせてください。

## 禁止事項
- 仕様が不明確なまま実装を開始すること。
- テストが失敗している状態で品質ガードに進むこと。
- 品質ガードに失敗したまま `retro` を呼び出すこと。
- ユーザーの明示的な指示なしに、既存の正常に動作しているコードを破壊すること。
